# A股十年周度主线回溯与周更流程

## 研究对象与时间边界

- 市场：A股。
- 回溯起点：2016-10-24 所在周；终点：当前已结束的最近一个交易周。每个研究单元按周一至周五划分，短周按实际交易日处理。当前未结束周可以列在队列中，但必须保持“未结束”，不得提前写成完整周结论。
- 周度判断只使用该周最后一个交易日收盘时已经公开的信息。周后发布的财报、政策解读和结果数据，单独放在“事后验证”，不得反向改变当周主线判断。
- 研究分两段：先按周补齐历史周报；历史队列结束后，每周分析刚结束的一周，并更新主线延续、切换或退潮状态。

## 每周分析步骤

1. 列出当周可见的政策、产业、公司公告和产品/订单事件，记录原始发布日期、发布时间、链接与来源类型。优先使用政府部门、交易所、上市公司公告和公司正式材料；媒体报道用于补充背景，不代替一手证据。
2. 从全市场涨幅、成交额、涨停与连板、上涨家数、龙头扩散度等行情线索中找出候选方向。行情只负责发现候选，不单独决定“主线”。
3. 对每个候选方向核对需求变化、利润落点、产业链位置、竞争壁垒、代表公司与主题关联证据。区分真实订单/收入/利润、政策预期、概念映射和纯情绪炒作。
4. 判断该周属于启动、扩散、加速、分歧、退潮或切换，并与此前周报比较，写出连续性证据和变化证据。
5. 写明市场已计价的预期、尚未计价的预期差、最可能推翻判断的反证，以及下一周需要观察的验证点。
6. 周报完成后才计算后续 1、4、12 周表现，作为事后验证字段；不将其用于当周标签和筛选。

## 历史分类与时点校验

- 行业成员有效区间和行业分类版本是两件事。计算某周行业收益前，必须确认分类代码及层级在该周已经存在，且成员关系在该周有效。
- 若当前行业分类在历史周之后才发布，不能因为成分股记录带有更早的 `in_date` 就把新分类回填到旧周。应找到当时的分类版本及官方/供应商交叉表，完成可审计映射；映射不清楚时停止行业排名并标注缺口。
- 概念指数也要检查指数发布日期和历史成分是否可获得，避免用今天的概念池定义过去的主题。

## 固定周报字段

- 周次、交易日范围、信息截止时间
- 市场状态与风险偏好
- 核心主线、次主线、轮动/补涨方向
- 主线阶段与置信度
- 关键一手证据（含日期和链接）
- 需求变化、利润落点、竞争壁垒
- 代表标的及其与主线的业务证据
- 已计价预期、潜在预期差
- 反证与失效条件
- 下一周观察清单
- 事后行情验证（与当周判断隔离）
- 数据缺口和无法确认的事项

## 已有资料与缺口

- 腾讯云数据目录于 2026-10-27 盘点：全市场日线原始缓存覆盖 2005-01-04 至 2026-10-12，另有 2026-09-01 至 2026-10-27 的近端行情补丁；申万原始行业文件和历史成员区间已存在。这说明十年价格历史基本具备，不代表涨停梯队、资金流、PIT 基本面及主题证据已齐备。
- 当前公告元数据为 4,324 条、1,178 个公司代码的定向样本，覆盖 2019-01 至 2026-06 的若干抓取窗口，不是全量连续公告库；检查到的公告 PDF 归档目录为空。2016-2018 及大量未抓取周仍需补逐周政策、产业新闻和公司公告证据。
- 时点财务/业务文件当前只有约 35 家公司的样本，不能代表全市场 PIT 基本面。需扩展至按每周公开时点可得的全市场财报，并处理披露时间、修订及可交易日。
- 历史行业成员区间还需核对分类版本当时是否存在；涨跌停复原需要时点证券状态与历史规则；扫描到的缓存范围未见独立资金流/融资融券文件。
- 详细目录、样本计数和后续缺口见[`腾讯云主线研究数据盘点（2026-10-27）`](tencent_data_inventory_20261027.md)。
- [`weekly_mainline_market_data.py`](weekly_mainline_market_data.py) 可用本机 `TUSHARE_TOKEN` 生成指数收益、全市场个股收益中位数和上涨占比快照；密钥不写入文件。该程序不做主题识别。

## 自动运行边界

当前 Codex 会话没有可调用的通用“创建周期自动化”工具。已确认本机 Codex CLI 可登录，但本次命令环境没有可用的网页搜索连接；因此不能把一个本机定时命令包装成“自动完成高质量主线分析”。可先用本流程逐批回溯；真正自动周更应运行在同时具备网页检索、历史资料访问和结果回传能力的定时任务环境中。任何调度都不应把 API 密钥写入仓库、任务参数或腾讯云。
